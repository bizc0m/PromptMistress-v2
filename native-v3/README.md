# PromptMistress V3 — migration sans serveur HTTP

La V3 est en construction à côté de la V2 installée. Le lecteur Swift des archives et des prompts reproduit les lignes, leur ordre et les détails du moteur V2 sur les données actuelles. L’extension V3 utilise Native Messaging (Comet, Chrome ou Edge) pour capturer et importer des conversations sans ouvrir de port local. L’import réutilise les modules Node existants à la demande.

## Bibliothèque native en aperçu

```sh
./native-v3/build-preview.sh
open dist/PromptMistress-V3-preview.app
npm run test:native-v3
```

Cette application distincte lit et recherche les archives et prompts existants sans ouvrir de port TCP. Elle synchronise automatiquement les nouvelles sessions locales Codex, Claude et Gemini à l’ouverture puis, par défaut, toutes les cinq minutes, avec le module Node embarqué. La navigation principale regroupe **Bibliothèque**, **Fusion / Lab** et **Importer**. La bibliothèque affiche les **Chats** par défaut ; aucune fiche Prompt n’est supprimée et le filtre **Prompts** ou **Tout** permet de les retrouver. Le nombre total de prompts conservés reste affiché dans le résumé de la liste. Chaque ligne affiche la taille du contenu en lignes et en Ko. Le mode **Lignes compactes** réduit la hauteur de 44 à 34 points tout en conservant le sous-titre. Les fiches Prompt de moins de **0,2 Ko** sont masquées par défaut dans la liste ; **Plus de filtres… → Prompts min. (Ko)** règle ce seuil, avec **0** pour tout afficher. La recherche, le type, la plateforme et le mode texte complet sont accessibles directement dans la bibliothèque ; les filtres avancés restent disponibles au besoin. Sélectionner une ligne ouvre sa lecture à droite. Le menu **Affichage du chat**, au-dessus du texte, propose la conversation complète, ses questions et prompts seuls, ses réponses seules, le texte source et la taille du texte. Dans la conversation, le premier message utilisateur porte la mention **Question 1 · Prompt initial**, les suivants **Question · Prompt de suivi**, et les messages assistant **Réponse**. Les questions et réponses ont des titres de couleurs distinctes. **Classer · Index** réunit l’édition locale du projet, des dossiers, des tags et des autres annotations avec l’export d’index dans le même panneau. Le projet d’origine reste dans la source ; sa modification locale pilote le filtre et l’explorateur V3. **Importer** affiche dans la même fenêtre la synchronisation locale, les fréquences, la capture des pages visibles, les préférences, les fichiers et les conversations reçues du navigateur. La liste des captures peut être filtrée et cochée avant import ; seules celles dont le texte est arrivé sont importables. Les fichiers JSON ChatGPT, JSON génériques, Markdown et texte sont acceptés. Pour un JSON contenant plusieurs conversations, un tableau permet de filtrer et de cocher les conversations à importer. Le menu **Coffres historiques** lance localement les commandes de recherche Node/Python, liste les prompts et projets Node, et importe Codex dans le coffre Python. Les commandes Node qui manipulent des entrées reprennent automatiquement les identifiants sélectionnés dans la bibliothèque. Le runtime Python installé avec la V2 est copié dans l’aperçu V3 lorsqu’il est présent. Les interfaces complètes des deux modules restent à migrer.

**Actualiser** synchronise immédiatement les sessions locales, relit la bibliothèque et vérifie la page LLM visible si la capture est active. Une barre indique la progression du scan et de l’indexation des fichiers Prompt. **Fichier → Fréquences d’actualisation…** règle séparément les sessions locales (manuel, 1, 5, 15, 30 ou 60 minutes) et la surveillance des pages visibles (5, 10, 20, 30 ou 60 secondes). Les valeurs sont conservées entre les lancements. La capture attend toujours 20 secondes de stabilité du texte avant l’import.

La bibliothèque native propose maintenant un **explorateur** par plateforme, projet, dossier hiérarchique et tag, un **tableau à six colonnes** (Date, LLM, Titre, Projet, Statut, Source) dont les largeurs et la visibilité sont réglables, le tri par en-tête, les **filtres** (type, visibilité, statut, dates, tri, texte complet et NyxBoolean), une **fiche intégrée** (tags, dossiers, note, statut, priorité et couleur), le masquage, l’archivage et la restauration par sélection, l’ajout groupé de tags et dossiers, la modification groupée du statut et de la priorité, les règles de classement, les vues sauvegardées, les tags favoris, la liste et l’enregistrement des pièces jointes déjà téléchargées, le lien source, un **navigateur paginé des réponses** avec le prompt précédent, les références et l’ouverture du chat source, les surlignages, la lecture épurée, la provenance, la copie, la comparaison de deux éléments et l’export d’une fusion éditable. **Fusion / Lab** reprend l’interface à deux panneaux avec les archives fournies directement par Swift. **Codex Exporter** ouvre son interface historique intégrée et charge automatiquement les chats Codex présents dans les coffres locaux ; le choix manuel d’un dossier reste disponible. Chaque ligne possède une case à cocher. **Cocher les résultats visibles** ajoute le filtre courant au lot ; **Tout décocher** vide ce lot. **Export groupé** exporte les éléments cochés, ou tous les résultats visibles si aucune case ne l’est. **Exporter** produit Markdown, texte, JSON, ZIP simple ou corpus complet ZIP, sur les éléments cochés, une sélection ou les résultats visibles, avec choix des versions et du contenu (tout, questions, réponses, brut) ; **Exporter un index** produit un index Markdown. Les annotations V3 sont enregistrées dans `~/.promptmistress-v2/v3-annotations.json`.

Le bouton **Affichage ▾** dans l’en-tête de la bibliothèque règle immédiatement l’unité de taille (lignes, Ko, les deux ou aucune), la densité des lignes, l’explorateur, les tags, le nombre de versions, les colonnes les plus utilisées, ainsi que des seuils prédéfinis pour masquer les prompts courts. **Réglages détaillés…** ouvre la liste de toutes les informations à afficher : chaque colonne a sa propre case et sa largeur. En plus des colonnes initiales, on peut cocher **Taille, Lignes, Tags, Dossiers, Priorité, Versions, Type, Note, Identifiant** et **Lien source**. Les nouvelles colonnes sont décochées par défaut. Ces choix sont conservés au redémarrage. Le panneau complet règle aussi la taille du texte et les couleurs des projets. Le menu **Organiser → Affichage de la bibliothèque** donne aussi accès à ce panneau ; il conserve l’état de l’explorateur, les tags et variantes visibles, les compteurs, la taille du texte, les dimensions des panneaux et le mode de couleur des projets (automatique, neutre ou couleur de fiche). La liste et l’explorateur distinguent les plateformes, projets, tags et statuts par couleur, comme dans la V2. Le menu **Fichier → Préférences d’import** choisit un coffre existant et le traitement des doublons. L’édition d’une fiche conserve son brouillon si elle est interrompue ; les brouillons V2 sont repris lors de la migration quand ils existent. Les coffres historiques Node et Python exposent maintenant leurs commandes CLI dans deux sous-menus, sans démarrer leurs anciens serveurs web.

Le menu **Organiser → Reprendre les annotations V2…** lit le stockage WebView de la V2. Il crée d’abord une sauvegarde `v2-webview-backup-*.json` dans `~/.promptmistress-v2/`, puis ajoute seulement les fiches absentes du stockage V3. Les règles, vues et tags favoris V2 trouvés sont repris si leurs équivalents V3 sont vides. Les brouillons V2 sont fusionnés sans écraser les brouillons V3 ; les principaux réglages d’affichage V2 sont repris si la V3 n’en possède pas encore.

Le menu **Fichier → Capture automatique des pages LLM visibles** active une capture native sans extension. Après l’autorisation macOS **Accessibilité**, la V3 lit les conversations affichées dans Chrome, Edge, Safari, Brave ou Arc sur les domaines LLM reconnus. Elle attend que le texte reste stable pendant 20 secondes, puis conserve la page dans le coffre. Ce mode est désactivé tant que vous ne l’avez pas activé. Il lit le texte visible, sans garantir les rôles des messages ni les pièces jointes ; il ne récupère pas les conversations restées cachées dans l’historique du site. Les pages trop longues sont signalées au lieu d’être enregistrées partiellement.

## Import automatique des historiques ChatGPT et Perplexity

Dans Comet, l’extension V3 importe ChatGPT. Comet n’exécute pas l’extension sur ses pages Perplexity dans la configuration vérifiée ; la V3 utilise donc un onglet Perplexity connecté de Comet via AppleScript pour cette source. Ce parcours demande le réglage Comet **Présentation → Options pour les développeurs → Autoriser JavaScript dans les événements AppleScript**. Sans ce réglage, **État des sources d’import** signale l’erreur et l’import Perplexity ne démarre pas. La V3 retente au lancement puis toutes les cinq minutes, importe uniquement les conversations renvoyées par Perplexity et ignore les doublons.

Dans Chrome ou Edge, l’extension V3 peut importer les deux sources. Le parcours Comet ci-dessus évite d’utiliser ces navigateurs.

Configuration initiale :

1. Charger `browser-extension-v3` comme extension non empaquetée dans Comet, Chrome ou Edge. Désactiver l’extension V2 pendant la vérification pour éviter deux captures concurrentes.
2. Exécuter `./native-v3/install-host.sh --comet` (ou `--chrome`, `--edge`) pour enregistrer le pont natif dans le navigateur choisi. Le pont n’autorise que l’identifiant de l’extension V3.
3. Dans la V3, ouvrir **Fichier → Préférences d’import**, choisir le coffre et cocher **Importer automatiquement ChatGPT et Perplexity**. Le réglage est activé par défaut si aucune préférence antérieure ne l’a désactivé.
4. Ouvrir ou recharger un onglet connecté à ChatGPT et un onglet connecté à Perplexity. Dans Comet, l’extension parcourt ChatGPT tandis que l’app native parcourt Perplexity au lancement puis toutes les cinq minutes. Dans Chrome ou Edge, l’extension parcourt les deux sites. Les conversations renvoyées sont importées dans le coffre ; les passages suivants ignorent les doublons. Une session Perplexity sans texte exploitable est comptée en échec et n’empêche pas l’import des autres.

Le bouton PM conserve la sélection manuelle et la page de capture. Le mode automatique respecte la préférence d’import : s’il est désactivé, aucune lecture d’historique ne démarre sans clic. Les erreurs de liste ou de capture sont signalées par **PM ⚠**. L’extension utilise les interfaces privées actuellement exposées par les sites ; une modification côté ChatGPT ou Perplexity peut interrompre la collecte. Les pièces jointes ne sont pas téléchargées par ce parcours. Les conversations absentes des listes fournies par les sites ne peuvent pas être garanties ; un export du compte reste le moyen de contrôler l’exhaustivité.

La capture de la page visible sur d’autres sites LLM reste manuelle via l’extension, ou facultativement automatique avec l’option macOS Accessibilité décrite plus haut. Le pont ne lance aucun serveur HTTP.

## Restant avant le remplacement de l’application V2

La V2 reste la référence fonctionnelle tant que chacun des parcours suivants n’a pas été migré et vérifié sur les données existantes :

1. Explorer, filtrer et rechercher : vérifier les préférences de colonnes reprises depuis une vraie installation V2 et le regroupement des lignes sur un échantillon réel.
2. Organiser : vérifier la migration des données WebView réelles des profils anciens et la parité des actions de classement.
3. Exploiter : contrôler la parité du corpus avancé et des index Codex/NotePlan sur les archives réelles.
4. Capturer : fichiers, sources locales et pages LLM visibles sans serveur ; signaler explicitement les pages non capturables et les pièces jointes manquantes.
5. Reprendre les interfaces riches des modules Node/Python, notamment les réglages d’export, sans port HTTP. Les commandes CLI et la sélection Node depuis la bibliothèque sont accessibles, mais leur interface historique n’a pas été reproduite.

Les annotations et vues de la V2 résident dans le stockage local de son WebView. La migration doit lire et convertir ces données avant de remplacer cet écran, sans les écraser avec des valeurs vides.

## Applications voisines

**NoteMistress d’abord** : la V3 embarque le binaire CHATDomina 0.2.2 construit depuis le module Swift de NoteMistress. **Fichier → Copier l’extrait pour NoteMistress** met un passage sélectionné en forme et le copie. **Fichier → Exporter le chat pour NoteMistress** utilise le mode Chat après confirmation de complétude et enregistre un Markdown compatible avec l’import de NoteMistress. Les pièces jointes ne sont pas transférées par cette action ; aucune note n’est modifiée automatiquement.

**TinyPlan ensuite** : le dossier `02-apps/TinyPlan` est vide. Les sources actives se trouvent dans `01-projets/_applications/TachesDuJour` et une copie de travail TinyPlan Lab existe séparément. Adapter le même format d’échange à son système de plugins quand le parcours NoteMistress sera stabilisé ; ne pas inventer une API TinyPlan dans PromptMistress.

Au lancement, la V3 vérifie les dossiers Codex, Claude et Gemini, puis la présence du pont et de l’extension dans Comet, Chrome ou Edge. Le résultat est enregistré dans `~/.promptmistress-v2/archives/import-health-v3.json` et consultable dans **Fichier → État des sources d’import**. Pour ChatGPT et Perplexity, le dernier contrôle réel est conservé séparément ; une session du site ne peut être confirmée que lorsque son onglet est ouvert.
